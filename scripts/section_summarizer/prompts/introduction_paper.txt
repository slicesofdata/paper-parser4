# Objective

Read the Introduction section under "SECTION TEXT" and return a JSON object matching the schema described below. Your extraction must be faithful. Do NOT infer content the paper does not state; do NOT supplement with outside knowledge.

# Special guidance for this section

Introductions vary enormously across papers. Some state theories explicitly and by name; others advance an unnamed explanatory account. Some list numbered hypotheses; others present predictions in prose. Your goal is to capture what the paper actually says, using this scholar's operational definitions:

- A THEORY, for this extraction, is ANY stated explanation for why the predictor should influence the outcome. It need not be labeled "theory" — it may appear as "we propose that," "we hypothesize that," "the account predicts that," or as an unlabeled mechanistic statement. Capture it regardless of what the authors call it.

- A HYPOTHESIS is a specific testable prediction derived from a theory, often tied to specific measurements. Distinguish theory (overarching mechanism) from hypothesis (specific prediction about specific variables/measures).

- MECHANISTIC CLAIMS are statements about HOW the predictor influences the outcome — mediators, moderators, boundary conditions, pathways.

# Extraction rules

1. FAITHFULNESS. Extract only what the paper states. Set unreported fields to null (single values) or empty arrays (lists). Add unreported items to `missing_or_unclear`.

2. GROUNDED FIELDS require verbatim quotes. For `theoretical_framework`, `specific_hypotheses`, and `mechanistic_claims`, each entry must include:
   - `topic_label`: a SHORT DESCRIPTIVE TAG (2-8 words) identifying the subject matter. This is NOT a claim, paraphrase, or interpretation. It just names the topic. Examples: "memorability-based rejection process", "role of word frequency", "distinctiveness heuristic". Do NOT include interpretive words like "robust", "supports", "confirms", "indicates", "demonstrates" unless those words name the topic itself.
   - `verbatim_quote`: the exact supporting text from the source (under 300 characters; preserve exact wording, punctuation, capitalization)
   - `citations_inline`: citations appearing within or immediately adjacent to that quote. ONLY external works — do NOT cite the current paper itself. If no citation appears in the quote, this array must be empty.

3. MULTIPLE ENTRIES ALLOWED. If the paper states the theory multiple times with different emphases, or advances multiple related hypotheses, create separate entries for each. Do not collapse them.

4. CITATIONS. Every external work referenced should appear in `citations_referenced` at the top level with authors, year, and context. Citations that fall within Evidenced quotes should also appear in that entry's `citations_inline`.

5. BACKGROUND RESEARCH. For each bullet in `background_research_summary`, cite the source inline in prose form: "Meeks and Marsh (2003) demonstrated that low-frequency items produce distinctive memory traces."

6. KEY TERMINOLOGY. Extract terms the authors explicitly define or introduce as specialized. Include the verbatim definition when they provide one.

7. ALTERNATIVE THEORIES. For each competing account discussed, describe it and explicitly contrast it with the focal theory (different variables, different mechanism, different predictions).

8. NO CRITIQUE. Do not evaluate theoretical adequacy, argument strength, or evidence quality. That analysis happens in a separate stage.

9. VALID JSON ONLY. Return a single JSON object matching the schema. No preamble, no code fences, no commentary.
